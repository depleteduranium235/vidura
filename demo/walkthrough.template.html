SPL Hit Adjudication

Vidura

SAP GTS blocks a business partner whenever its name resembles an entry on a sanctioned party list. Someone then has to decide whether it is genuinely that party. Most are not — but each one still has to be read, reasoned about, and documented. This agent does the reading and lays out the evidence; a fixed rule, not the model, sets the disposition.

A walkthrough, not the running app. These are five illustrative cases with synthetic business partners and SPL entries — invented for demonstration, not real screening results. The reasoning and evidence below is genuine output from the adjudication pipeline. The Fiori app itself currently runs locally against a mock OData service; it is not deployed to SAP and not connected to AGP.

How evidence is classified

A fixed scale, from rules-it-out to confirms-it
1Dispositive Exclusion Identity is impossible
2Strong Discriminator Very unlikely
3Weak Discriminator Mildly reduces likelihood
4Neutral No information either way
5Weak Corroborator Mildly increases likelihood
6Strong Corroborator Identity likely
7Dispositive Confirmation Identity established

How a case is produced

01

GTS is read, never written

The blocked partner, its addresses and every matched SPL entry are read over OData. One case is created per partner-address-to-entry pair, so each identity question is judged on its own.

02

The model fills the ledger

It compares the two records element by element and classifies each finding on the scale above, with a written justification. Missing data is recorded as neutral — absence of evidence is never treated as evidence of absence.

03

A fixed rule sets the band

The disposition comes from the ledger by deterministic logic that is non-compensatory: one dispositive finding outweighs any number of opposing weak ones. The model never emits a score, and no number is ever the reason for a decision.

Worth knowing before you read too much into it

  • The agent proposes; it does not release. Executing a release stays with a named human in their own SAP session, under their own user ID.
  • Auto-clear is shown for completeness but is not reachable yet — it requires a matching precedent, and the precedent store is still a stub.
  • The reasoning has been proved against live GTS data in the AGP sandbox, but that system's partner records carry almost none of the discriminators real adjudication needs, so quality still has to be demonstrated on a client extract.
