SPL Hit Adjudication

Vidura

SAP GTS blocks a business partner whenever its name resembles an entry on a sanctioned party list. Someone then has to decide whether it really is that party. Most are not — but each one still has to be read, reasoned about and documented, and the documentation is what an auditor asks for. This agent does the reading and lays out the evidence; a fixed rule, not the model, sets the disposition.

These are screenshots of the working application. It runs on demo data — five illustrative cases with invented business partners and SPL entries, not real screening results. The reasoning shown is genuine output from the adjudication pipeline. The app currently runs against a local mock OData service; it is not yet deployed to SAP and not connected to a GTS system.

How a case is produced

01

GTS is read, never written

The blocked partner, its addresses and every matched SPL entry are read over OData. One case per partner-address-to-entry pair, so each identity question is judged on its own. Releasing a block stays with a named human in their own session.

02

The model fills the ledger

It compares the two records element by element and classifies each finding, with a justification. Missing data is recorded as neutral — absence of evidence is never treated as evidence of absence.

03

A fixed rule sets the band

The disposition follows from the ledger by deterministic, testable logic: one dispositive finding outweighs any number of weak ones opposing it. The model never emits a score, and no number is ever the reason for a decision.

Where this stands

  • The UI is Fiori Elements on SAPUI5 1.120 — a List Report and Object Page generated from OData annotations, not hand-built views.
  • The reasoning has been run against live GTS data in the AGP sandbox and the read path works end to end. But AGP's partner records carry almost none of the discriminators real adjudication needs, so quality still has to be proved on a client extract.
  • Auto-clear exists in the design but is not reachable yet: it requires a matching precedent, and the precedent store is still a stub.
